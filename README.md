# Eleanor 网站使用说明

当前网址：[Eleanor](https://nkhszkqaq.github.io/eleanor/)。仓库已由 `memorial-site` 改名为 `eleanor`；请使用新网址分享。同一浏览器在旧地址看过开场的记录会自动沿用。

这是可直接打开、可部署到 GitHub Pages 的独立静态礼物网站（统一首页 + 语音贺卡独立页 + 相册独立页）。没有后端、数据库、构建流程、外部字体或第三方脚本。已加入用户提供的背景音乐；已加入 18 张用户提供的原图；九人录音仍待提供。

## 1. 替换素材与文案

- 九个人的真实录音放到 `assets/audio/voices/01.mp3` 至 `09.mp3`；原始音乐保存在 `assets/audio/song.mp3`，当前播放副本为 `assets/audio/song-stream.mp3`。
- 在 `content.js` 的 `voices` 数组中填写每人的 `name`、可选 `note` 与 `src`。姓名和寄语默认留空，页面只显示编号；增删对象也可改变信封数量。旧版 `audio.message` 已被 `voices` 数组替代。
- 当前照片为 `assets/photos/01.jpg` 至 `18.jpg`，均与提供的 JPG 文件逐字节一致，未压缩或转码。没有文件时显示占位，播放器显示“音频暂不可用”，未知时长显示 `--:--`。
- 用文本编辑器打开 `content.js`。`hero.title` 与 `hero.body` 均留空；`hero.reserveSpace: true` 保留首页空白文案区域。开场的 `opening.title`、`opening.body` 同样留空，`opening.reserveSpace: true` 保留空白区域。只有填写经确认的真实文案后才显示文字；设为 false 可取消对应的空白预留。浏览器标签页名称仍为 Eleanor。
- `audio.song.title` 当前为文件名中的「天使にふれたよ!」，`credit` 为同一文件名中的「椎名モンブラン」（不是额外查证的演唱者信息）；留空时仍可显示“音乐”。音频路径在各自 `src` 修改。`audio.song.volume` 控制默认音量（0–1，当前 0.2）；`audio.song.autoplay: true` 表示每次打开页面尝试低音量播放（优先于拆包播放设置）；`audio.song.playAfterOpening: true` 表示主动拆开礼物后开始播放，设为 false 可恢复手动播放。
- `photos` 数组增删对象即可增减照片，**没有固定总张数上限**，当前配置为 18 张。每项支持 `src`、`alt`（无障碍描述）、`caption`（可选说明）及可选 `width`／`height`（预留原始比例）。清空数组会显示“暂无照片”。
- 照片默认每批追加 24 张，接近底部时自动追加；也可点击“加载更多照片”。`photoBatchSize` 控制每批数量（1–100），不限制总数。照片墙预览懒加载，查看器可切换到尚未追加缩略图的照片。实际容量取决于图片体积、设备内存与网络，不代表无限存储。
- 文件夹新增照片后仍需把相应路径加入 `photos`，纯静态网页不会自动扫描文件夹。
- `labels` 集中配置功能标签与状态提示；`pageTitle` 是浏览器标签页标题。配置均按纯文本显示，不解析 HTML。
- 三个页面都位于项目根目录，素材路径相对于当前 HTML，请使用 `assets/...` 或 `./assets/...`，不要以 `/` 开头。文件名大小写必须完全一致。
- 使用真正的 MP3 音频和 JPG／PNG／WebP 照片；不要只修改扩展名。HEIC 请先转换格式。当前按要求保留原图，通过懒加载减少首次请求；查看大图时仍需下载对应原文件。

目录中的 README 用于保留素材目录；没有空白 MP3／JPG 假文件。

## 2. 本地预览

直接双击 `index.html` 即可；无需安装依赖。也可以在本目录运行：

```sh
python3 -m http.server 8080 --bind 127.0.0.1
```

浏览器访问 `http://127.0.0.1:8080/`；终端按 Ctrl+C 停止。如果系统没有 Python，直接打开 HTML 即可。

首页使用柔和包装纸与丝带开场，轻触／点击后约 1.15 秒进入首页。同一浏览器首次展示时写入持久记录，刷新、新标签页、关闭浏览器后重新打开均不会自动重播；无重播入口。旧版会话记录会迁移，已经看过的用户无需再拆。可随时跳过或按 Esc 进入；键盘和系统“减少动态效果”直接进入。`opening.enabled` 可关闭开场，提示在 `labels` 配置。只有主动点击／键盘激活拆包后，才在首页出现时让背景音乐以约 20% 的软件音量淡入；拆包动画期间静音，加载期间跳过或直接 Esc 不触发音乐。记录仅存于当前浏览器：换设备、无痕窗口或清除网站数据会视为首次；若持久存储被禁用，会尝试会话记录，全部存储被禁用时无法保证跨次记忆，但仍可正常进入网站。

原始音乐 `assets/audio/song.mp3` 保持不变（3,645,565 字节）。当前播放 `assets/audio/song-stream.mp3`，是 96 kbps MP3 有损播放副本（2,185,552 字节），由 GitHub Pages 托管，不嵌入 HTML／JS。音频元素默认 `preload="none"`；当前自动播放配置会在打开页面时尝试请求音乐，点开信封才请求录音，照片预览按需懒加载。浏览器缓存可复用已请求素材。当前歌曲时长由本地 MP3 实测为 182.073469 秒，记录于 `audio.song.metadata`。播放前显示 `0:00 / 3:02` 和“点击播放”，无需下载音频；进度调整仍在浏览器取得真实时长后才启用。实际播放后以浏览器报告的时长和进度为准；缺失或损坏文件仍显示错误和 `--:--`，不伪造播放进度。更换音频时需更新或移除 metadata；metadata.src 与歌曲 src 不一致时忽略预存时长。

在 HTTP／HTTPS 下使用 Web Audio 的 GainNode 控制低音量；在 file:// 或缺少 Web Audio 的浏览器上使用原生音量回退。实际听感还取决于设备音量；部分移动浏览器可能限制原生音量控制。浏览器若拒绝播放，会显示提示并保留播放按钮，不伪造播放成功。参见 [MDN 自动播放说明](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay)。刷新或再次访问不会自动重复开场；音乐会重新尝试自动播放。可随时使用播放器暂停。

只需分享首页的一个网址。首页 `index.html` 放置音乐、语音贺卡入口和相册入口；`voices.html` 是独立的九人语音贺卡页，`photos.html` 是独立相册页，两页都有返回首页链接。点击信封才加载对应录音；打开信封不自动播放。开始录音时会暂停音乐；切换信封或关闭信纸会暂停旧录音。三个页面使用同一首歌，跳转页面会尝试从头自动播放；浏览器历史缓存恢复不会强制续播。点击进度条、拖动滑块或聚焦滑块后按方向键调整进度。进度和时长来自浏览器实际媒体状态；文件不可用时可以重试，持续加载超过 15 秒会提供重试提示。

信纸可以用上一份／下一份按钮或左右键切换；焦点位于音频进度条时，左右键只调整进度。Esc、关闭按钮或遮罩可关闭并恢复焦点。

照片墙使用奶油色纸边、低饱和度图钉和轻微倾斜，手机单列、平板双列、桌面三列，保持照片完整比例。图钉仅为 CSS 装饰，不修改图片。18 张照片合计 12,444,115 字节，文件名、尺寸及 SHA-256 对照见 `assets/photos/originals.json`。用户指定的 ChatGPT 截图未加入。

点击照片打开查看器；前后按钮或左右方向键循环切换。Esc、关闭按钮或图片区域之外的遮罩可关闭。Tab 在查看器按钮间循环，关闭后返回原照片按钮和原滚动位置。只有一张照片时前后按钮禁用。

## 3. GitHub Pages 最短部署步骤

1. 解压 ZIP，把**解压后的内容**放入你选择的 GitHub 仓库的 `main` 分支根目录：根目录应直接看到 `index.html`、`voices.html`、`photos.html`、`styles.css`、`script.js`、`content.js`、`.nojekyll` 与 `assets/`。不要在仓库根目录再套一层 `memorial-site/`。替换好素材后提交上传。
2. 仓库 **Settings → Pages → Build and deployment → Source → Deploy from a branch**；选择 **main** 和 **/(root)**，点击 **Save**。
3. 等待 Pages 发布任务成功，打开 Settings → Pages 给出的网站地址。项目站点通常是 `https://你的用户名.github.io/仓库名/`。首次上线后再核对真实音频与照片。

以上步骤依据 [GitHub 官方发布源说明](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site) 和 [入口文件要求](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)。本项目使用相对路径并包含 `.nojekyll`，无需 npm、构建命令或环境变量。

## 开场图案

开场保持细丝带、小结、长尾、深酒红色及奶油白包装纸。点击后丝带移开，完整包裹短暂停留，随后整个开场淡出进入首页；没有包装纸分裂或碎片飞散。

两张本地无损 WebP 图经过细节增强，仍为 1536×1024，合计约 1.75 MiB；仅在需要展示首次开场时请求。与此前 JPEG 相比文件较大，但编码不再丢失生成图中的像素细节。素材及生成提示词见 `assets/artwork/README.md`。`opening.artwork.image` 和 `opening.artwork.paper` 配置两张图，SVG 的丝带分层坐标与当前构图对应；更换构图需同步调整裁切区域。

主图加载失败或等待超过 12 秒会直接进入首页；纸张图层缺失则使用完整主图淡出。加载期间仍可跳过。已访问者不会再次下载开场图案，也不会因为视觉更新而被要求再次拆包。无第三方运行时依赖。

## 媒体加速

18 张原图仍保持不变；照片墙优先使用 `photos[].preview` 指定的 WebP（全部共 1,538,018 字节），点击查看器再下载 `src` 原图。未配置或加载失败的预览会回退原图。预览最大 960×1280，保留比例和显示方向，不裁切。新增照片可省略 preview，或自行生成预览并配置相对路径。更换原图时请一并更新预览。

音乐播放副本为 96 kbps MP3，音质存在有损编码取舍，原始音频保留；若希望恢复原文件播放，将 song.src 和 metadata.src 同时改为 assets/audio/song.mp3。当前 autoplay 开启时会在进入页面后请求音乐；关闭 autoplay 后才恢复手势后请求。实际首次出声受网络连接和浏览器缓冲策略影响；本地测速结果和范围见 VERIFICATION.md。

## 默认播放（当前行为）

`audio.song.autoplay: true` 优先于旧拆包播放设置：首页、相册、语音页每次新加载时直接尝试以 20% 音量播放，包括开场显示期间。浏览器允许时无需点击；若有声自动播放被拦截，显示真实提示，并在首次点击或 Enter／空格操作时重试。播放器按钮仍可手动启动。手动暂停后不会因为点击页面再次播放；录音与音乐仍互斥。自动播放受浏览器策略限制，不能保证所有手机无需操作即可出声。设为 false 可恢复此前的主动拆包后播放行为。
